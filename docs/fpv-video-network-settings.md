# FPV 图传网络设置

“设置 → FPV 图传网络”会列出当前已启用网卡上的非回环 IPv4 地址。选择的地址用于 MediaMTX 的 WHEP HTTP 监听和 WebRTC UDP 媒体监听。

- 应选择浏览器所在网络能够访问的设备地址。
- FPV 视频播放期间不能修改监听地址。
- 保存值写入用户设置，并在地址仍属于活动网卡时优先于 `API_FPV_VIDEO_WEBRTC_HOST`。
- 如果保存的地址在启动时已经失效，服务会回退到环境变量配置并记录警告。

## RTMP 同步推流

“设置 → RTMP 推流”保存一个 `rtmp://` 或 `rtmps://` 目标地址。默认关闭且地址为空；启用时地址必须包含有效主机和推流路径。

- 使用内置 MediaMTX 播放或录像时，MediaMTX 在 `127.0.0.1:18554`（可用 `API_FPV_VIDEO_INTERNAL_RTSP_PORT` 调整）开放内部 RTSP/TCP 代理，后端内置的纯 Go 发布器复用同一上游视频并推送目标地址。配置外部 WHEP 且不录像时，播放继续使用外部 WHEP，发布器直接读取 `API_FPV_VIDEO_RTSP_URL`，RTMP 启动失败不会切换或阻断现有播放路径。
- 发布器支持复制 H.264/H.265 视频轨，不推送音频、不做转码；源编码不是 H.264/H.265 时停止重试并显示失败，目标 RTMP 服务不兼容时会显示错误并重试。
- 推流连接失败按 1、2、4、8、10 秒退避重试，成功输出视频后重置退避。失败不会停止本地 WebRTC 播放或录像。
- 关闭视频会话时先取消 RTSP/RTMP 客户端并等待发布器退出，再停止 MediaMTX，同时取消尚未执行的重试。
- 视频会话期间不能修改启用状态或目标地址；关闭会话后保存，下一次查看时生效。
- 设置页通过现有 5 秒运行状态轮询显示“等待视频、正在连接、推流中、重试中、推流失败”，错误信息不会包含目标地址、URL 用户信息或查询参数。

发布器作为 Go 后端的一部分随主程序编译和分发，无需安装或携带 FFmpeg。它使用与 MediaMTX 1.19.0 对齐的 Go RTSP/RTMP 协议库，只进行协议封装转换，不包含视频编解码器。
