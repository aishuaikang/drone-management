# 继电器现场输入控制与干扰报告

现场通过 X1～X8 输入触发继电器后，系统根据实际 Y1～Y8 输出状态更新大屏，并为每一路输出建立“现场控制”干扰报告。输出闭合时开始记录，输出断开时结束记录并计算持续时长。现场控制没有平台请求时长，页面与 CSV 的“请求时长”显示为 `-`。

## 设备配置

使用智嵌配置软件，在“输入状态改变时”选项中开启“关联到输出”和“自动上报状态”，保存设置并重启设备。两项功能出厂默认关闭，详见《8路网络继电器控制器用户使用手册 V1.1》6.3、6.4 节（手册第 29 页，PDF 第 33 页）。输入接线及有效电压须按实际设备型号和手册 3.5、4.2 节确认。

继电器继续使用 TCP_SERVER 模式。后台通过现有 `API_INTERFERENCE_RELAY_HOST`、`API_INTERFERENCE_RELAY_PORT`、`API_INTERFERENCE_RELAY_ADDRESS`、`API_INTERFERENCE_RELAY_TIMEOUT_MS` 连接设备；不需要新增平台配置。后台占用一条持续监听连接，ASCII 控制使用另一条短连接，设备最多支持四个 TCP 客户端，应为后台预留连接数。

系统不会自动修改设备参数或下发 DI 联动配置，也不会把输入信号转为额外的开启指令。关联到输出由设备执行，平台只监测实际输出并记录。

## 协议与记录规则

依据手册 7.1.1.1 节表 7.1，集中状态帧为 15 字节：`48 3A 地址 命令 DATA1…DATA8 校验和 45 44`。校验和取前 12 字节之和的低 8 位，DATA1～DATA8 分别对应第 1～8 路，状态 `01` 有效/闭合，`00` 无效/断开。

| 命令 | 含义 | 平台处理 |
| --- | --- | --- |
| `0x41` | DI 输入状态 | 触发一次 DO 状态查询；单独收到 DI 有效不会创建干扰报告 |
| `0x53` | 查询全部 DO 状态 | 建立监听连接时及每秒发送，补充自动上报并在重连后恢复实际状态 |
| `0x54` | DO 输出状态 | 更新大屏；为未被平台操作覆盖的已闭合输出创建现场控制报告，确认断开后结束报告 |

监听处理 TCP 拆包、粘包和连续状态变化，并校验帧头、帧尾、设备地址、校验和及八路状态。ASCII 指令应答中的二进制自动上报会被分离，不影响现有软件控制。

- 每路现场输出分别记录；重复上报和周期查询不会重复创建记录。
- 平台手动干扰、无人值守操作的回报沿用原报告，不重复记作现场控制。
- 断线表示状态未知，不视为输出已断开；重新连接后根据实际状态继续或结束原记录。
- 后台退出或重启时，尚未闭合的报告按现有规则标记为异常。启动时发现已开启的设备侧输出，会以首次观察时间创建新的现场记录；协议不包含历史动作时间。
- 报告页面每两秒刷新，列表和 CSV 都保留“现场控制”类型。

状态协议没有携带操作者或触发来源。因此“现场控制”表示未由当前平台操作发起的设备侧输出，也可能来自其他客户端或设备定时控制，不能仅凭报文可靠区分具体来源。

## 联调检查

1. 开启上述设备配置，确认后台能连接继电器。
2. 使 X1 输入有效，确认对应 Y1 实际闭合，大屏显示该通道开启，报告出现一条运行中的“现场控制”记录。
3. 撤销输入，确认 Y1 实际断开，报告结束并显示持续时长。
4. 对其他通道重复测试，并确认多路同时开启后分别关闭时，各路记录独立结束。
5. 从页面发起一次手动或无人值守干扰，确认只生成对应的平台操作记录。
6. 关闭大屏后进行现场操作，再打开报告页面确认仍有记录；测试断线重连，确认不会把断线误记为正常结束。
